# 叙事实验室：把经历讲成听者能跟上的故事

## 使用规则

用于讲经历、复述、面试故事、失败说明、转述他人观点和开场引入（S43—S48、S55、S56、S04、S06等）。先收用户的原样讲述，再从下面挑**一个**视角反馈。叙事保真优先：不为了好听而虚构细节、夸大冲突或替用户补情绪。

## 六个视角

### 1. 口头经历的六个部分
社会语言学对口头经历叙事的经典分析给出六个部分，可用来检查听者缺了哪一块：

| 部分 | 回答的问题 | 缺了会怎样 |
|---|---|---|
| 摘要 | 这是个关于什么的故事？ | 听者不知道该注意什么 |
| 定向 | 谁、何时、何地、当时什么状况？ | 听者对不上人和背景 |
| 复杂化 | 然后发生了什么变化？ | 没有事，只有背景 |
| 评价 | 为什么这件事值得讲？对你意味着什么？ | 听完会问“所以呢？” |
| 结果 | 最后怎样了？ | 悬而未决 |
| 尾声 | 回到现在：和此刻的听者有什么关系？ | 故事和当下的话题脱节 |

诊断问：只问缺得最多的一块，例如“听者现在知道发生了什么，但还不知道这件事为什么值得讲——它对你改变了什么？”
不要求每个故事六块俱全；一句话致谢可能只需要复杂化和评价。

### 2. 事件顺序与讲述顺序
发生的顺序（故事）和讲出来的顺序（讲述）可以不同：
- **顺叙**：适合流程、复述通知、需要听者跟着做的事。
- **结果先行（倒叙）**：适合汇报、面试回答、忙碌听众——先说结果，再说经过。
- **插叙**：在关键处补一段背景；超过一次容易让口头听者迷路。
练法：把用户的一段顺叙重排为结果先行，比较哪个版本更适合当前听众。

### 3. 视角与聚焦：谁在看，谁在说
- 讲经历时区分“我当时知道的”和“我现在才知道的”，避免后见之明（见[thinking-toolkit.md](thinking-toolkit.md)）。
- 复述他人观点时用“他认为……”“在他看来……”标出人物声音，再用“我的看法是……”标出自己的声音；两者混在一起，听者分不清哪是原意。
- 一个事件多方在场时，可用[快局G11](quick-games.md)从不同视角各讲一次，再整合。

### 4. 叙事速度：场景与概述
- **场景**：放慢，给对话、动作、具体细节，用在转折点。
- **概述**：一句带过一段时间，用在过渡。
- **省略**：跳过与听者任务无关的部分。
常见问题：在不重要的过渡上用场景铺陈，到了关键转折反而一句带过。
练法“场景放大镜”：请用户选出故事里最关键的一个瞬间，只用30秒把这一刻讲具体（谁说了哪句话、看到了什么），其余全部概述。

### 5. 转折与张力
听者被吸引，往往是因为“原本以为……，结果……”。讲经历时点明原来的预期，再讲出乎预期之处，最后讲你怎样应对。张力来自真实的落差，不来自夸张形容词。

### 6. 连贯不等于因果
故事要求前后相连，讲述者容易为了顺而补上“因为”。复盘、失败说明、研究介绍中，要把“我看到的”和“我推测的原因”分开说（叙事谬误）。诊断问：“这个‘所以’是当时就知道的，还是讲的时候补上的？”

## 四个练法

| 练法 | 一次只给的任务 | 检查 |
|---|---|---|
| 六块卡片 | 用一句话各说摘要、复杂化、评价、结果 | 缺哪块；评价是否具体 |
| 一事三讲 | 同一件事分别讲给小满、港务长、面试官；每次只讲一位 | 事实不变，顺序、细节与词汇随听众变 |
| 倒叙重排 | 把刚才的版本改为结果先行 | 第一句是否给出听者最需要的结果 |
| 场景放大镜 | 选一个瞬间讲30秒细节，其余概述 | 速度分配是否服务重点 |

## 叙事伦理

只讲用户愿意分享的经历；涉及他人时用匿名代称，不暴露隐私。面试和答辩中的故事必须真实，教练只帮助组织与取舍，不编造经历或成果。复述他人时忠实于原意，有不确定处标出“我理解的是……”。
